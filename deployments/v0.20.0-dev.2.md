## Four implemented corrections

1. An hourly interval containing an official high/low event is labeled as such. At T3 2026-09-28 09:10, the display says '干潮を含む時間' and the next low remains 09:20; the positive 09:00-to-10:00 hourly difference no longer claims an instantaneous rise. Inclusive hourly boundaries are handled conservatively. Missing anchors remain unknown.
2. Every chart has a cm scale. Gray dashed lines mark official high/low times without forcing the hourly interpolation to pass through the official extrema. Missing strokes and fills remain segmented. Midnight retains 00:00 with the calendar date on another row.
3. Each rendering saves an immutable, local-only snapshot and links its opaque ID. It contains the exact formatted explanation, tide data and relevant original JMA daily records, and the weather/marine payloads and metadata used for that rendering. A later guide tap does not choose another place/time or fetch new provider data. '最新に更新' is a separate action. Missing, corrupt or expired snapshots explicitly report unavailability instead of substituting fresh data.
4. Solar labels use 日没 / 日の出 with a next-day prefix where applicable. Small charts use a readable text summary. Duplicate footer timestamps were moved to the snapshot detail. The header retains the display reference time and forecast cards retain valid times and units.

Snapshots are retained for at most 7 days and at most 128 records. At high update frequency the count limit can shorten retention. Only the new snapshot directory is pruned. Existing preferences, forecast caches and recovery files are not removed. Snapshot write failure is visible. The local checksum detects accidental corruption; it is not a cryptographic authenticity claim. Deep links contain no coordinates. The existing loader still downloads code/manifest when run, so 'no new provider fetch on guide tap' does not mean the entire loader is network-free.
