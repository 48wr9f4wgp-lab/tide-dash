## Incident

Native Full Evidence on an existing fixed 伊東 spot showed:
- `対象区域: 未確認`
- `安全情報取得: ...（区域未対応）`

Root cause:
- the device's saved `fixedStation` was created before JMA warning-area metadata existed;
- the new curated `spots.json` had the correct area code, but the saved station object was an older local copy.

This was a metadata migration defect, not a JMA warning-parser defect.

## Fix

### 1. Reject old spot-catalog cache for safety use

The local `TideDashSpots.json` cache is no longer considered valid for the safety layer unless every curated spot carries resolved JMA warning-area metadata.

An old seven-day cache therefore cannot mask the new mapping.

### 2. Hydrate saved fixed spots automatically

On fixed-location startup:
- if the saved station already has JMA warning metadata, use it unchanged;
- if it is a fishing-port record with administrative metadata, keep the existing port path;
- otherwise, load the current curated spot catalog;
- match by spot id, then conservative name/coordinate fallback;
- merge the latest metadata into the saved station;
- persist the hydrated station back into preferences.

The user does **not** have to reselect the fishing spot.
